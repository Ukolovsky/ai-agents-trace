СЛОЙ 2

Как это технически исполнено в пилоте

As-is Швецъ. Основной БП заказа + ФО по товарам и материалам (карточка: поля процесса, клиент-контрагент, вложенные ФО; почта отдельно). Параллель с ~8 типами системных БП BP3 готовим со Сергеем.

Контур заказа · блоки 1–6

ИНТЕГРАЦИЯ

1. Каналы

Система принимает письмо и создаёт заказ. Отдельный бэкенд CPQ, IMAP / исходящая почта. В BP3 как есть не переиспользуем. Нужен контур управления каналами через интеграции.

АГЕНТ · RAG · BP2

2. Обработка заказа

Пайплайн агентов разбирает письмо; RAI маршрутизирует к нейросети; RAG ищет аналоги по каталогу. BP2 держит этапы, переменные и два ФО. Цель: агент импорта + бизнес-промпт / семантика пресета. Magic Pad: быстрые команды (хардкод под пилот).

ХАРДКОД

3. Уточнение остатков

Каталоги товаров и материалов не сущности BP2: хардкод + интеграция (файл / API / 1С). Каталог хранит данные и обновляет RAG. Остатки готового и сырья, закупки при дефиците. В BP3 нужно переделывать: динамические таблицы или хранилище + агент-интегратор.

ХАРДКОД

4. Конфигурация

Хардкод вне BP3, но близко к целевому: дерево товара (костюм: два поддерева), BOM, админка мастер-дерева. Нужен ревью; методику имеет смысл подтвердить на другом клиенте. В первую версию BP3 не тащим, отдельный инкремент позже.

ХАРДКОД

5. Оценка предложения

Себестоимость / рекомендованная цена и бизнес-логика ценового предложения. Формулы и коэффициенты снаружи BP2 (в т.ч. подстановка суммы после этапа): хардкод, конструктор не единый, нужен ревью. В BP3 нужно платформенное решение.

BP2 · ХРАНИЛИЩЕ · GenAI

6. Генерация КП

Генерация КП из полей BP2 + хранилище документов BP + GenAI. Вложения и сгенерированные документы в карточке. В BP3: документ + хранилище + улучшенный GenAI.

Блоки управления

ХАРДКОД

Каталог товаров

Не сущность BP2. Хардкод + интеграция; каталог хранит, в RAG шлют обновление. Админка: потребность vs остаток готового, закупка при дефиците. В BP3 переделывать: динамические таблицы или хранилище + интегратор.

ХАРДКОД

Материалы

Как каталог товаров: не BP2, хардкод + интеграция. Сверка BOM с остатками, закупка сырья, админка. В BP3 тот же контур, что у товаров (таблицы / интегратор).

ХАРДКОД

Конфигурации

Мастер-дерево для операционного конфигуратора. Хардкод вне BP3, близко к целевому, на ревью. В первую версию переноса не входит.

BP2

Пользователи

Клиент и контрагенты BP; доступы и роли пользователей уже есть в BP. В BP3 переиспользовать контрагентов и роли платформы.

ХАРДКОД

Аналитика по заказам

Сроки заявок и этапов без правки заказа. Хардкод простой админки. Длительности этапов не в v1 BP3 по бэклогу enablement.

СЛОЙ 3

Как реализовать в BP3

Предзаполнено идеями из review 25.08. Жёлтые ячейки можно править. «+ шаг» добавляет экран или пункт ревью под этот ID. «Сохранить» пишет таблицу в git.

Разбирайте каждый экран: допишите шаг, целевой объект BP3 и комментарий. Параллель с ~8 типами системных БП уточняем со Сергеем.
