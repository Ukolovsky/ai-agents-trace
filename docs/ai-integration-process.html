Процесс интеграции AI-сервиса

  1. Приём прототипа из R&D: прототип приходит в AI-команду с пакетом переноса: демо, описание задачи, контракты, известные ограничения. Затем идёт совместная сессия нарезки на задачи. Решение о передаче принимают продакт R&D и продакт AI
  2. TDR — аппрувнутый целевой вариант, в состав TDR входит:
    1. Контекст задачи (какую проблему закрывает и цель, в общих словах, своим языком, коротко)
    2. КОРОТКОЕ описание микросервиса
    3. Описание контрактов микросервиса (вход, выход, время запроса, комментарии)
    4. Flow решения, которое предлагается между клиентом, BFF, микросервисом
    5. Запрос на реализацию правок/добавлений в BFF/Монолите, коротко своими словами, что предлагается реализовать
      • Зачем нужно:
      • Скольким агентам и сервисам нужно:
      • На каком временном решении живём сейчас:
    6. Инфраструктурная схема (та самая общая)
  3. Разработка:
    1. При необходимости — переделываем TDR, переделываем общую архитектуру в случае инфраструктурного блока, пересогласовываем
    2. При нехватке вещей со стороны БП (пример — filemanager), пишем свой костыль для закрытия функционала
  4. Сначала ревью МИКРОСЕРВИСА и/или изменений в BFF/Монолите с нашей стороны. В ревью учитывается:
    1. Файловая структура https://wiki.yandex.ru/homepage/business-pad/development/guidlines/backend/fajjlovaja-struktura/
    2. Общие правила написания кода https://wiki.yandex.ru/homepage/business-pad/development/guidlines/backend/obshhee/
    3. Нейминг https://wiki.yandex.ru/homepage/business-pad/development/guidlines/backend/nejjming/
    4. Логика работы микросервиса
    5. Конечный результат
    6. Возможность на словах описать проведенную работу
  5. Деплой на AI dev
  6. Тестирование/доработки
  7. Деплой на AI prod
  8. 6.1. Пилот у клиента с Enablement (по решению CPO) (необязательный шаг)

Шаги 1–6 сервис проходит изолированно в AI-контуре. С шага 7 начинается интеграция в сервис BP. Решение об изоляции фиксируется на TDR

  1. Ожидание, пока backend отдел закроет все необходимые пробелы со стороны платформы
  2. 7.1. После релиза БП пересобрать и проверить агентов на обновлённом Dev (плановая адаптация в первом спринте после релиза)
  3. Рефактор, перевод на новые фичи платформы
  4. Передаем на ревью/написание бэкенду необходимых коннекторов на стороне BFF/Монолита
  5. DevOps — запрос на разворачивание инфраструктуры
  6. Интеграция на дев
  7. Стандартный флоу тестирования
  8. Прод
