Процесс интеграции AI-сервиса

  1. TDR — аппрувнутый целевой вариант, в состав TDR входит:
    1. Контекст задачи (какую проблему закрывает и цель, в общих словах, своим языком, коротко)
    2. КОРОТКОЕ описание микросервиса
    3. Описание контрактов микросервиса (вход, выход, время запроса, комментарии)
    4. Flow решения, которое предлагается между клиентом, BFF, микросервисом
    5. Запрос на реализацию правок/добавлений в BFF/Монолите, коротко своими словами, что предлагается реализовать
    6. Инфраструктурная схема (та самая общая)
  2. Разработка:
    1. При необходимости — переделываем TDR, переделываем общую архитектуру в случае инфраструктурного блока, пересогласовываем
    2. При нехватке вещей со стороны БП (пример — filemanager), пишем свой костыль для закрытия функционала
  3. Сначала ревью МИКРОСЕРВИСА и/или изменений в BFF/Монолите с нашей стороны. В ревью учитывается:
    1. Файловая структура https://wiki.yandex.ru/homepage/business-pad/development/guidlines/backend/fajjlovaja-struktura/
    2. Общие правила написания кода https://wiki.yandex.ru/homepage/business-pad/development/guidlines/backend/obshhee/
    3. Нейминг https://wiki.yandex.ru/homepage/business-pad/development/guidlines/backend/nejjming/
    4. Логика работы микросервиса
    5. Конечный результат
    6. Возможность на словах описать проведенную работу
  4. Деплой на AI dev
  5. Тестирование/доработки
  6. Деплой на AI prod
  7. Ожидание, пока backend отдел закроет все необходимые пробелы со стороны платформы
  8. Рефактор, перевод на новые фичи платформы
  9. Передаем на ревью/написание бэкенду необходимых коннекторов на стороне BFF/Монолита
  10. DevOps — запрос на разворачивание инфраструктуры
  11. Интеграция на дев
  12. Стандартный флоу тестирования
  13. Прод
