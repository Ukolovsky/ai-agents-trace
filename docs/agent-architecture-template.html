00. Тип поставки и путь разработки

Заполняется первым, до паспорта. Правила и чеклист TDR по типам: .cursor/skills/bp-ai-docs/references/delivery-type.md. Без выбранного типа документ не идёт на TDR.

Поле Значение
Тип поставки А микросервис / Б сервис-исполнитель / В встроено в монолит BP / Г конфигурация на платформе
Почему этот тип по критериям 0.2 референса
Граница с ядром BP контракт через BFF, общий API как автоматический пользователь, события file manager, очередь: все стрелки к ядру
Что берём у платформы file manager, S3 по presigned URL, LLM-шлюз, Keycloak, кластер; только через контракт или стандартную оболочку
Свои данные своя база (какая), что хранится, где текст и артефакты
Нефункциональные требования память, CPU и GPU, скорость p95, качество по метрикам, мультитенантность
Зависимости от платформы задачи с номером, через планирование и Егора, волна
Версия схемы под релиз ссылка
Статус TDR не начат / подготовлен / пройден / с замечаниями, дата, протокол

  • [ ] Путь файлов только через file manager и S3, между сервисами ссылки.

0. Паспорт агента

Поле Значение
Назначение Одна фраза: какую работу снимает с человека
Класс Generative / Predictive / Agentic / Workflow — и почему
Способ встречи Assist / Embedded / Autonomous-first / Semantic
Умения Understand, Generate, Reason, Advise, Execute… — только реальные
Самостоятельность L1…L5 и что именно агент делает сам
Роль человека in-the-loop / on-the-loop / in-command
Риск низкий / средний / высокий / критический — и почему
Паттерн один runtime / несколько агентов / детерминированная цепочка / ReAct
Владелец ответа пользователю кто отдаёт результат в канал
Отвергнуто что сознательно не делаем (swarm, handoff, свободный цикл…)

Источники: аналитика (BRD, FR, UC), TDR, протоколы решений, код. Список с датами редакций.

1. Канал (User Query)

Откуда приходит работа. Для каждого входа: контракт входа (текст, файл, событие), контекст вызова (сессия, тенант, экземпляр), чего ждёт вызывающий (реплику, черновик, итог), лимиты входа.

2. Gateway и Auth

Кто принимает вызов, где аутентификация, где изоляция тенанта, где авторизация на действия. Какие проверки выполняются до агента.

3. Application Core

Какие доменные сервисы хранят истину и выполняют запись. Каким API агент их зовёт. Агент сам в операционную базу не пишет — кто пишет за него.

4. Agent Pattern и runtime

Один runtime или несколько агентов, кто владеет ответом, где выполняется (сервис, движок), таймауты, повторы, отмена, пауза на человеке и где хранится состояние паузы.

5. Pipeline: шаги

Шаги работы по порядку, развилки и их условия. Есть ли цикл; если есть — условие выхода (схема, лимит кругов, человек, эскалация). Если нет — написать «линейная цепочка».

6. Reasoning и выбор модели

Где решает модель, а где правило кода. Какие модели на каких шагах, через что они вызываются, по какому измеримому сигналу переключаемся на сильную модель или на человека. Лимит контекста и что делаем при переполнении.

7. Tool Execution

Полный список инструментов таблицей: имя, класс (чтение / поиск / запись), хозяин данных, когда вызывается, нужна ли пауза на человеке. Как ограничен список (allowlist) и где фильтр результата перед моделью.

Инструмент Класс Хозяин данных Когда Пауза на человеке

8. Human Validation

Где пауза перед побочным эффектом, что человек видит, что обязан поправить, что подтверждает одним действием, что происходит при отмене. Права человека на подтверждаемые действия.

9. Stress testing и входные правила

Что отсекается до рассуждения и что проверяем нагрузкой. Для каждого сценария — ожидаемое поведение.

Сценарий Ожидаемое поведение Статус

10. Data Processing

Подготовка данных вне запроса пользователя (распознавание, нарезка, индексация) — отдельно от пути запроса. Если такой подготовки нет — N/A с причиной.

11. Database Layer

Каждое хранилище: что лежит, хозяин, кто читает и кто пишет, протокол. Отдельно: где состояние задачи агента. Если движок не выбран — так и написать.

Хранилище Что лежит Хозяин Читает Пишет

12. Evaluation

Метрики и пороги, эталонные наборы, где они лежат, как правки человека становятся разметкой. Evaluation — офлайн, не шаг цепочки.

13. Логи и наблюдаемость

Что пишется в трассу на каждую задачу (поля), как маскируются ПДн, что считается аудитом (подтверждение человека) и где он хранится.

14. Версии и повторяемость

Что версионируется (промпты, модель, пакет знаний, инструменты), где номер версии пишется в задание, можно ли повторить прогон и чего не хватает.
