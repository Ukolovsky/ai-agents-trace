0. Паспорт агента

Поле Значение
Назначение Превращает входящий документ в проверенный человеком комплект экземпляров процессов BP: основной, зависимые (контрагенты, товары), связи; для торгового документа — материальный поток с позициями. Либо сохраняет документ в базу знаний тенанта (W2)
Класс Generative (извлечение полей) + Predictive (тип документа, ранжирование процессов). Исполнение — детерминированный workflow: шаги задаёт профиль, модель работает внутри шагов и инструменты не выбирает
Способ встречи Embedded (действие «Импорт с ИИ», документ этапа) + Assist (Magic Pad) + Semantic (поля и правила через W1/W2)
Умения Understand, Generate, Reason (сопоставление), Execute — только после подтверждения человеком
Самостоятельность L3: сам распознаёт, извлекает, ранжирует и собирает план; любая запись — после человека
Роль человека in-the-loop: обязательная проверка и одно подтверждение комплекта
Риск Средний: пишет в процесс и может создать финансовую операцию, но только после подтверждения и от имени пользователя; наружу не действует; в документах бывают ПДн
Паттерн Один runtime, профиль «Импорт», фиксированная цепочка шагов
Владелец ответа пользователю Оверлей проверки BP (Magic Pad) или форма этапа
Отвергнуто Несколько агентов; передача договора в AI-06; свободный ReAct-цикл; запись в BP моделью или сервисом извлечения; «создать всё» без проверки

Источники: - Бизнес-требования AI-04 (BR-AI04-01…32), Спецификация требований AI-04 (FR/NFR/EVAL-04), Сценарии использования (UC-AI04-1…9), Концептуальная модель, Точки входа и сценарии, Решения по полю вне схемы и многострочному импорту (редакция 21.09.2026), US-AI04 v1.3. - TDR «Импорт документа через копилот» (целевое решение), протокол TDR-ревью 03.08.2026. - ТЗ «Как описывать и рисовать архитектуру агента» v3.2. - Код сервиса извлечения — только для пометок «есть».

Вход Контекст вызова Чего ждёт вызывающий Статус

B: документ этапа, исполнитель этапа — AI-04 экземпляр, этап, настройки этапа (от среды BP) результат на форме этапа; отдельного уведомления нет (FR-AI04-19) целевое
  • Контракт входа: один файл (PDF, DOCX, XLSX, PNG, JPEG; .jpg/.jpeg), до 10 МБ, до 50 страниц OCR; необязательный сопроводительный текст с намерением («создай контрагента») — приоритетнее автоклассификации (FR-AI04-49).
  • Отдельного вопроса «экземпляр или тенант» нет: контекст задаёт способ вызова (FR-AI04-46).
  • Почта не самостоятельный вход (US-AI04-003). Пакетный импорт — вне объёма.

2. Gateway и Auth

  • Gateway — BFF. Принимает вызов канала, видит сессию и тенант, проксирует в сервисы. есть
  • Аутентификация — Keycloak (OIDC) до BFF; агент личность не добывает. есть
  • Тенант и изоляция — тенант и пользователь из доверенного контекста; задача импорта доступна только владельцу и его тенанту, одинаковый файл у двух тенантов не раскрывает чужой результат (NFR-AI04-9, AC-AI04-12/13). целевое
  • Входные правила до распознавания: расширение и формат (ERR-FORMAT), размер (ERR-LIMIT-SIZE), страницы (ERR-LIMIT-PAGES), антивирус (FR-AI04-05), DLP (FR-AI04-42), проверка адреса файла на внутреннюю сеть и редиректы (NFR-AI04-10). Размер и расширение — есть в сервисе извлечения; остальное — целевое, сервисы антивируса и DLP — TBD.
  • Авторизация на действия — не в gateway: права BP (RM-3-001) проверяет Application Core до показа действия и повторно перед записью.

3. Application Core

Хозяин данных — монолит BP (new_arch), вызывается через BFF. Агент в операционную базу не пишет.

  • Параметры инициации выбранного и зависимых процессов: allow_on_init, is_required_on_init, default_value, validation_rules; допустимые состояния, этапы, автосценарии (FR-AI04-47). целевое (чтение init-параметров на Dev — есть).
  • Права «Создание», «Смена этапа», «Добавление», изменение схемы процесса — отдельно по каждому объекту, повторно перед записью (FR-AI04-25). целевое
  • Запись комплекта одним подтверждённым планом: основной и зависимые экземпляры, связи с ролями, материальный поток с N позициями, черновик по правилам процесса; итог по каждому объекту; повтор не создаёт дублей (FR-AI04-53, AC-AI04-10). Создание отдельных сущностей — есть в демо; план, черновик, позиции — целевое.
  • Добавление поля в схему через API монолита, затем перечитывание схемы (FR-AI04-57…61). целевое
  • Файловое хранилище BP и временный URL на исходник. целевое (DEP: контракт хранилища).
  • Блокер: модель позиций материального потока в бэке не построена — многострочный результат пока невозможен.

4. Agent Pattern и runtime

  • Паттерн: один runtime, один профиль «Импорт». Специализаций внутри нет, handoff нет. Владелец ответа — оверлей BP.
  • Где выполняется. Целевое: профиль на общем runtime агентов вне монолита; BP хранит каталог агентов и умеет их вызвать (решение ревью 03.08). Сейчас: шаги ведут фронт (оверлей) и BFF, сервис извлечения — отдельный узкий маппер «файл + схема → поля». есть / целевое
  • Таймауты и повторы: время до оверлея ≤ 2 мин (NFR-AI04-1); вызовы модели и OCR — таймаут и один повтор с задержкой; запись в BP — идемпотентный повтор. Конкретные значения — TBD.
  • Пауза на человеке: задача импорта в статусе «Проверка в оверлее» хранит распознанные значения и план (FR-AI04-63). Где хранится задача — TBD (раздел 16).
  • Отмена: статус «Отменён», из неподтверждённого плана ничего не создаётся, временные файлы удаляются по политике хранения (FR-AI04-35/36). Истечение сессии в оверлее — незавершённое сопоставление не сохраняется (FR-AI04-37).
  • Статусы задачи: Загружен → Обработка → Готов к проверке → Проверка в оверлее → Подтверждён (процесс | wiki) → Завершён | Ошибка | Отменён.

5. Pipeline: шаги

Линейная цепочка, цикла нет. Единственный возврат — после «+ поле»: перечитать схему и повторно сопоставить одно значение без новой загрузки файла (FR-AI04-58); это повтор шага 4, а не цикл модели.

# Шаг Что делает Развилка / исход Статус
1 Приём файл по ссылке + контекст запуска — есть
2 Входные правила формат, лимиты, антивирус, DLP, адрес нарушение → ошибка, распознавание не запускается частично
3 Распознать общий OCR-сервис: текст, координаты, таблицы нечитаемый → ERR-IDP-READ, другой файл есть внутри сервиса извлечения, вынос — целевое
4 Извлечь поля схема процесса + подсказки W1 + правила клиента W2; позиции таблиц — отдельным вызовом 0 полей → предупреждение, поток идёт дальше есть (без W2)
5 Ранжировать процессы среди процессов тенанта по содержанию и покрытию полей тип < 0,70 или равные одноимённые → выбирает человек частично
6 Участники и товары поиск существующих экземпляров: ИНН — ключ контрагента; артикул, имя — товара неоднозначно → «требует внимания» частично (справочники)
7 Дубликат? номер + дата + контрагент, не хэш файла найден → открыть / создать недостающий / всё равно новый целевое
8 Действие однозначный prompt → сразу; иначе вопрос в чате процесс · W2 · отмена целевое
9 Оверлей человек проверяет и подтверждает (раздел 8) отмена → ничего не создано частично
10 Запись и итог проверка параметров и прав, запись плана, итог по объектам (U4) частичный результат не маскируется целевое

6. Reasoning и выбор модели

  • Решает модель: значения полей и позиций, тип документа и ранжирование процессов, имя экземпляра, есть ли значение в документе (проверка «+ поле»).
  • Решает код: пороги, дубликаты, права, параметры инициации, маршрут шагов, формат ответа. LLM-планера нет.
  • Модели. Сейчас одна модель на все шаги, temperature 0, ответ строго JSON. есть Целевое: вызовы через общий шлюз моделей платформы — сервис-прокси с единым API к провайдерам, ключами, лимитами и учётом стоимости. Какой сервис — TBD.
  • Правило эскалации (Router):
  • уверенность типа < 0,70 или разрыв первого и второго кандидата < 0,10 → процесс выбирает человек (FR-AI04-15/51);
  • уверенность поля < 0,70 (распознавание или сопоставление) → обязательная правка;
  • сильная модель — опция: один повторный прогон только неуверенных полей, включается по результатам eval, не по умолчанию. TBD
  • Порог 0,70 и разрыв 0,10 — рабочие до калибровки. TBD
  • Контекст: до 50 страниц; в модель идут текст документа, таблицы и узкий пакет полей выбранного процесса, не весь архив. Длинные таблицы — порциями строк. Размер порции — TBD.

7. Tool Execution

Протокол — REST через BFF. MCP не используется. Модель инструменты не выбирает: вызовы задаёт код профиля, поэтому вызов вне списка невозможен по построению. Формальный allowlist runtime — FR-AI04-55/56, следующий срез. Ответ модели проходит фильтр (JSON-схема, типы полей) до показа человеку.

8. Human Validation

  • Где пауза: между сборкой плана и записью — на ребре к побочному эффекту.
  • Что видит человек: документ слева, поля справа с уверенностью распознавания и сопоставления; шаги «Общие данные», «Документ», «Контрагенты», «Товары» — только если данные есть.
  • Обязан поправить: поле или тип ниже 0,70; неоднозначное сопоставление; недостающие обязательные параметры.
  • Поле вне схемы — отдельное состояние, не порог. «+ поле» доступно при праве изменять процесс; значение проверяется по документу, при неудаче — выделение фрагмента и повторный OCR; своё подтверждение (FR-AI04-57).
  • Подтверждает одним действием весь комплект: состав, состояния, этапы, связи, влияние автосценариев (FR-AI04-45).
  • Права проверяются до показа действия и повторно на сервере; недоступное действие показано с причиной.
  • Отмена — ничего не создано; ранее подтверждённое добавление поля не откатывается.
  • После записи — итог по объектам (U4); частичная запись не показывается общим успехом.

10. Data Processing

  • Распознавание — отдельный общий OCR-сервис для импорта, договора и индексации W2. Парсер текстового слоя (PDF, DOCX, XLSX), OCR сканов (PNG, JPEG, PDF-скан), layout: страница, координаты слов, ячейки таблиц. Выход — текст + координаты + таблицы; координаты нужны для подсветки источника поля и проверки «+ поле». Сейчас OCR встроен в сервис извлечения как временное решение. целевое
  • Временные файлы распознавания удаляются по политике хранения (FR-AI04-36, NFR-AI04-8). TBD сроки.
  • Ветка W2 (контур семантического слоя): импорт передаёт документ, MD-описание и метаданные (задача-источник, раздел, автор, дата, тип); нарезку, эмбеддинги и индекс делает контур W2. Только по выбору «Сохранить в базу знаний», экземпляр не создаётся (FR-AI04-30…34). целевое

13. Логи и наблюдаемость

Трасса на каждую задачу импорта. есть (базовая), поля ниже — целевое (FR-AI04-40).

  • Спаны: ocr, extract, classify, match, verify, commit.
  • Поля трассы: trace_id, id задачи, тенант и пользователь (хэш), процесс, import_fork (process | wiki), semantic_pack_id (версии W1 и W2), версия промпта, модель, уверенность по каждому полю (распознавание и сопоставление), число полей «требует внимания», правки человека по полям, время шагов, токены, стоимость.
  • ПДн в трассе маскируются (FR-AI04-39).
  • Аудит подтверждения (кто, когда, какой комплект) — журнал аудита BP (FR-AI04-28); Langfuse его не заменяет.

14. Версии и повторяемость

  • Версионируются: промпты (git sha), модель, пакет семантики W1 + W2 (semantic_pack_id), версия OCR, хэш схемы процесса. Всё это пишется в задачу и в трассу. целевое
  • Повтор прогона: сегодня один в один нельзя — версии в задании не пишутся. После записи версий — повтор по трассе при temperature 0 без гарантии бит-в-бит у провайдера.
  • Повторный импорт документа: дубликат определяется по номеру, дате и контрагенту (FR-AI04-43); решение за пользователем. Повторное сопоставление после изменения схемы использует новую схему (AC-AI04-11).
