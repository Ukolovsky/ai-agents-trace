Персональные цели

Александр К. - Lead

  1. Паспорт агента введён: шаблон утверждён, паспорт есть у каждого агента в работе.
  2. Технологический выбор обоснован: модели и фреймворк оркестрации сравнены на наших задачах, решение зафиксировано в TDR.
  3. Целевая архитектура AI-решений описана и согласована с Максимом и Мироном: оркестрация, общий MCP-сервер, Semantic Layer, eval-контур, контур безопасности и их границы с core product.
  4. Бизнес-аналитика: для ключевых сценариев описаны AI capabilities и бизнес-метрики, по которым судим об успехе.

Алексей - агентная логика, AI Security

  1. Паттерны оркестрации для команды: на наших кейсах разобрано, где workflow, где агент, где multi-agent (supervisor / sub-agents, длительные сценарии с паузой).
  2. Политика безопасности агентов: уровни действий, права на tools, approval, audit trail.
  3. Агентный сценарий в production: проектирует и доводит до запуска реальный агентный сценарий - с TDR, обработкой сбоев, работой через общий MCP-сервер и evals.
  4. Каркас агента для команды: оркестрация, state, fallback, логирование, подключение к MCP, политика безопасности по умолчанию.

Александр Д. - Backend, MCP, качество кода

  1. Code quality: линтеры, форматеры, type-чекеры и pre-commit настроены во всех AI-репозиториях и проверяются в CI.
  2. Правила для AI-агентов разработки: шаблон AGENTS.md / CLAUDE.md (проект, соглашения, команды сборки и проверок, ограничения) лежит в каждом активном проекте и поддерживается в актуальном состоянии.
  3. Общий MCP-сервер в production: контракты tools (схемы, ошибки, идемпотентность), версионирование, логирование вызовов; используется минимум двумя агентами.
  4. Интеграция с core product: бизнес-операции, нужные агентам, доступны через API и MCP; изменения согласованы с бэкенд-командой и оформлены в TDR.

Личное: перестроить свою работу под разработку через агентов и научиться отфильтровывать поток сгенерированной информации теми же агентами.

Дмитрий - Evals, пайплайны, Semantic Layer

  1. Первый eval для агента пресетов ОКВЭД (формирование бизнес-процессов): golden set, метрики, повторяемый прогон.
  2. Eval-контур для сервисов: автоматические evals в пайплайне для нескольких сервисов, регрессия при смене модели, промпта или tools, включая проверку выбора tools и тесты безопасности (prompt injection, excessive agency, утечка данных).
  3. Semantic Layer W1: ключевые бизнес-сущности описаны (атрибуты, связи, правила, допустимые действия) и привязаны к tools MCP-сервера; есть порядок версионирования.
  4. Наблюдаемость сервисов: трейсинг вызовов LLM и tools, стоимость и задержки видны на дашборде.

Паспорт агента - черновик

Паспорт дополняет TDR: TDR фиксирует решение один раз, паспорт описывает агента как живую единицу и обновляется вместе с ним. Каждый раздел заполняет владелец своей зоны.

Ритм

Раз в месяц короткая встреча, 5–10 минут на человека: что продвинулось по четырём целям, что мешает. В конце срока - итог по целям.
