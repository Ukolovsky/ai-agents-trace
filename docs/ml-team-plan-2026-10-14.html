План развития ML-команды

Четыре пункта, которые каждый берёт изучить и реализовать. Роли совпадают с местами в ТЗ: лид, инженер агентов, инженер интеграции, инженер качества.

Саша Котовенко, лид

  1. Целевая архитектура AI-решений описана и согласована с Максимом Цветковым и Мироном: оркестрация, общий MCP-сервер, Semantic Layer, eval-контур, контур безопасности и их границы с core product.
  2. Паспорт агента введён: шаблон утверждён, паспорт есть у каждого агента в работе.
  3. Технологический выбор обоснован: модели и фреймворк оркестрации сравнены на наших задачах, решение зафиксировано в TDR.
  4. Бизнес-аналитика: для ключевых сценариев описаны AI capabilities и бизнес-метрики, по которым судим об успехе.

Лёша Шремзер, инженер агентов

  1. Агентный сценарий в production: проектирует и доводит до запуска реальный агентный сценарий, с TDR, обработкой сбоев, работой через общий MCP-сервер и evals.
  2. Паттерны оркестрации для команды: на наших кейсах разобрано, где workflow, где агент, где multi-agent (supervisor и sub-agents, длительные сценарии с паузой).
  3. Политика безопасности агентов: уровни действий, права на tools, approval, audit trail.
  4. Безопасность встроена в агентов: агенты работают по политике безопасности.

Александр Дорожинский, инженер интеграции

  1. Качество кода: линтеры, форматеры, type-чекеры и pre-commit настроены во всех AI-репозиториях и проверяются в CI.
  2. Правила для AI-агентов разработки: шаблон AGENTS.md и CLAUDE.md (проект, соглашения, команды сборки и проверок, ограничения) лежит в каждом активном проекте и поддерживается в актуальном состоянии.
  3. Общий MCP-сервер в production: контракты tools (схемы, ошибки, идемпотентность), версионирование, логирование вызовов. Сервер используют минимум два агента.
  4. Интеграция с core product: бизнес-операции, нужные агентам, доступны через API и MCP. Изменения согласованы с бэкенд-командой и оформлены в TDR.

Личное: перестроить свою работу под разработку через агентов и научиться отфильтровывать поток сгенерированной информации теми же агентами.

Дмитрий Кульбида, инженер качества

  1. Первый eval для агента пресетов ОКВЭД (формирование бизнес-процессов): golden set, метрики, повторяемый прогон.
  2. Eval-контур для сервисов: автоматические evals в пайплайне для нескольких сервисов, регрессия при смене модели, промпта или tools, включая проверку выбора tools и тесты безопасности (prompt injection, excessive agency, утечка данных).
  3. Semantic Layer W1: ключевые бизнес-сущности описаны (атрибуты, связи, правила, допустимые действия) и привязаны к tools MCP-сервера. Есть порядок версионирования.
  4. Наблюдаемость сервисов: трейсинг вызовов LLM и tools, стоимость и задержки видны на дашборде.
